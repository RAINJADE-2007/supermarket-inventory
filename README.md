# 超市商品库存信息管理系统：四人填写框架

对应附件第14题，语言为 C++11。此工程提供公共数据结构、函数接口、主菜单和输入输出接线；14个业务函数留为 TODO，由你们填写。

**当前可编译、可打开菜单，但业务逻辑尚未实现。** 未填写的函数返回 `Status::NotImplemented`，界面显示“尚未实现”，不会把空结果当作查询结果，也不会假装保存成功。

## 0. 浏览器工作台

直接用浏览器打开 [web/public/index.html](web/public/index.html)，可浏览随项目提供的三条商品、按编号／名称／类别筛选、按单价或库存排序，以及查看低库存预警和分类统计。示例中的洗衣液库存为 8，低于预警值 10。

联调 C++ 工作区时，在仓库根目录运行下列命令。需要 Node.js 18 或更新版本和支持 C++11 的 `g++`，无须安装 npm 依赖。

```sh
npm run build
npm start
```

浏览器打开 [本地库存工作台](http://127.0.0.1:4174)，切换到 **C++ 工作区**。新增、编辑、出入库、查询、排序和文件操作都调用同一套 C++ 接口。业务模块仍由小组填写。接口返回 `NotImplemented` 时，前端会显示对应的任务编号。示例数据可通过 **数据文件 → 导入示例** 调用 D1 导入。C++ 工作区的数据随本地进程结束而清空，实现 D2 后可先导出留存。

`npm run build` 在 `build/bin/` 中生成命令行程序 `supermarket` 及浏览器适配器 `inventory_web`，Windows 上两者文件名均带 `.exe`。PowerShell 中也可用 `npm.cmd run build` 和 `npm.cmd start`。若使用 CMake，可执行 `cmake -S . -B build` 和 `cmake --build build`，再执行 `npm start`。端口和适配器路径可分别通过 `INVENTORY_PORT` 与 `INVENTORY_WEB_BIN` 设置。

若 Windows 下的 MinGW 因含中文用户名的临时路径而报错，可把 `INVENTORY_BUILD_TEMP` 指向有写入权限、仅含英文字母和数字的路径，例如在 PowerShell 中执行 `$env:INVENTORY_BUILD_TEMP = 'D:\msys64\tmp'`，再运行编译命令。

### 扩展位置

| 层次 | 位置 | 职责 |
| --- | --- | --- |
| C++ 业务 | `include/inventory.h`、`src/product.cpp`、`src/stock.cpp`、`src/query.cpp`、`src/data_io.cpp` | 保留顺序表和金额整数分表示，由四位成员按 A–D 分工完善 |
| 命令行入口 | `src/main.cpp` | 菜单、录入和输出，复用 C++ 业务接口 |
| 浏览器适配 | `web/native/inventory_web.cpp` | 管理一个 C++ 商品表，按业务状态返回结构化结果 |
| 本地服务 | `web/server.mjs` | 提供页面与 `POST /api/action`，串行调度 C++ 并处理中转文件 |
| 浏览器界面 | `web/public/` | `api.js` 管理调用和示例预览，`app.js` 管理交互和数据显示 |

完成业务模块后可独立扩展界面。例如添加库存流水时，先确定记录的数据结构和出入库成功后的写入规则，再增加适配器查询、API 操作与浏览器视图。扩展筛选、视图或导出时，沿用现有 `Status` 和 `ProductList` 契约。`npm run check` 可检查前端和本地服务的 JavaScript 语法。

扩展 API 时，在 `web/server.mjs` 的 `actionFields` 中声明操作及字段顺序，在 `web/native/inventory_web.cpp` 接入该操作对应的 C++ 函数，并让前端通过 `inventoryApi.request` 调用。响应统一包含 `status`，仅在成功时读取 `data`。统计响应将 `totalValueFen` 写成十进制字符串，以保留超出 JavaScript 安全整数范围的分值。

## 2. 编译与运行

在工程根目录执行，编译器需要支持 C++11：

```bash
g++ -std=c++11 -Wall -Wextra -Wpedantic -Iinclude src/main.cpp src/product.cpp src/stock.cpp src/query.cpp src/data_io.cpp -o supermarket
./supermarket
```

Windows 的 MinGW g++ 可以使用：

```bat
g++ -std=c++11 -Wall -Wextra -Wpedantic -Iinclude src/main.cpp src/product.cpp src/stock.cpp src/query.cpp src/data_io.cpp -o supermarket.exe
supermarket.exe
```

使用 Dev-C++ 或 Code::Blocks 等 IDE 时，新建 C++ 控制台项目，将 `src` 中的5个 `.cpp` 全部加入同一项目，添加 `include` 为头文件搜索目录，并启用 C++11。**只编译 `main.cpp` 会出现链接错误，因为业务函数在其他源文件里。** 源文件和示例数据使用 UTF-8；显示中文时使用支持 UTF-8 的终端。

相对文件路径以程序运行时的工作目录为准。建议把工作目录设为工程根目录；也可以在菜单输入完整文件路径。

## 3. 共用数据结构

```cpp
struct Product {
    std::string id;
    std::string name;
    std::string category;
    long long priceFen = 0;
    int stock = 0;
    int warningStock = 0;
};

struct ProductList {
    Product data[MAX_PRODUCTS];
    int size = 0;
};
```

这是“结构体数组＋当前长度”的顺序表。仅 `data[0]` 至 `data[size - 1]` 是有效商品。四个模块操作 `main` 创建的同一份 `ProductList`；不要分别创建互相独立的全局商品表。查询结果使用 `vector` 返回副本，商品的主存储仍是顺序表。

规则固定如下：

1. 商品编号唯一，按字符串精确匹配；编号、名称、类别不能为空或只有空白。
2. 三个字符串字段不能含制表符、换行、回车，保证文本文件可解析；普通内部空格允许。
3. 单价按“分”保存。输入 `300` 代表3元；单价范围 `0..MAX_PRICE_FEN`。
4. 库存和预警值范围 `0..MAX_STOCK`；预警条件为 `stock <= warningStock`。
5. 新增商品允许设置初始库存；之后修改商品信息不改变编号和库存。库存变化交给出入库函数。
6. 所有业务函数成功返回 `Status::Ok`，失败返回具体状态。未实现时保留 `NotImplemented`，不要提前改成 `Ok`。
7. 输出参数只在返回 `Ok` 时使用。查询无匹配项属于成功，返回空结果；按编号查找无结果则返回 `NotFound`。
8. 失败时不能破坏原商品表。查询、统计、排序、保存都使用 `const ProductList&`，不能改变原表。

## 4. 每个人具体填写什么

### 第1人：商品管理

| 编号 | 函数 | 完成后的行为 |
| --- | --- | --- |
| A1 | `findById` | 在有效范围内按编号查找；找到则写入下标并返回 `Ok`，否则返回 `NotFound` |
| A2 | `addProduct` | 验证字段、编号唯一和容量，成功时把商品加入顺序表并更新长度 |

先完成 A1。A2、A3及出入库模块可调用它。核心边界是重复编号、表满、商品不存在、负数价格和非法字符串。

### 第2人：出入库与预警

| 编号 | 函数 | 完成后的行为 |
| --- | --- | --- |
| B1 | `stockIn` | 验证编号和操作数量，成功后增加库存；不能超过 `MAX_STOCK` |
| B2 | `stockOut` | 验证编号、数量和可用库存，成功后扣减库存 |
| B3 | `findLowStock` | 返回库存小于或等于预警值的商品 |

操作数量必须为 `1..MAX_STOCK`。先验证再修改，避免出库失败仍扣库存。基础功能完成后，可自行增加出入库流水作为扩展；当前接口未预设日志实现。

### 第3人：查询与统计

| 编号 | 函数 | 完成后的行为 |
| --- | --- | --- |
| C1 | `queryByName` | 名称包含关键词即匹配；空关键词按非法输入处理 |
| C2 | `queryByCategory` | 类别精确匹配；分类功能通过商品的类别字段实现 |
| C3 | `sortProducts` | 返回按价格或库存排序的副本；主排序相同则按编号升序；原表顺序保持不变 |
| C4 | `calculateStatistics` | 计算商品种类数、库存总数量、库存总金额 |

商品种类数是有效记录数；总数量是库存数之和；总金额是各商品单价乘库存后的总和。金额结果保持“分”单位，由主程序转换显示。空表的统计结果应为0，分类结果为空。

| 编号 | 函数 | 完成后的行为 |

## 5. 文件格式

使用 UTF-8 的制表符分隔文本，首行必须为以下6个字段，字段之间是真实的 Tab：

```text
id    name    category    price_fen    stock    warning_stock
```

上面只说明字段顺序；复制格式请以 `data/sample_products.txt` 的真实字节为准。每条记录一行，不允许缺字段、多字段、无效数值、重复编号和超容量。最后一行有没有换行均应支持，Windows 行末回车应妥善处理。文件只有合法表头时，表示合法的空商品表。

建议状态约定：文件无法打开或读写失败返回 `FileError`；内容格式错误返回 `InvalidInput`；重复编号返回 `DuplicateId`；超容量返回 `CapacityExceeded`。导入失败不部分写入原表；保存时先写同目录临时文件并检查成功，再替换目标，替换失败要保留旧文件并返回失败。

## 6. 推荐填写顺序

1. 四人一起阅读头文件，确认所有参数和返回状态。
2. 第1人先完成 A1，再完成 A2；其他人可先用手工构造的测试商品表开发自己的函数。
3. A2 完成后，通过菜单1加入几条商品，即可逐步联调出入库、查询和统计。
4. 最后联调三种输入、保存及重新导入。所有人共同演示完整流程。

每完成一个函数，替换其 TODO 占位代码。`(void)参数;` 只是消除未使用参数的警告，实现后可删除。不要删除函数定义，只留声明，否则会链接失败。

## 7. 完成业务后的验收清单

这些是你们填写后的检查目标，当前占位程序不具备这些业务能力。

| 场景 | 预期结果 |
| --- | --- |
| 导入示例文件 | 3种商品、总库存78、总金额450.00元 |
| 示例表中编号1001入库20 | 库存由50变为70 |
| 接着编号1001出库8 | 库存变为62 |
| 再出库100 | 提示库存不足，库存仍为62 |
| 新增已有编号1001 | 提示编号重复，商品表不变 |
| 操作数量为0或负数 | 提示输入不合法，商品表不变 |
| 查询不存在的名称 | 返回成功但结果为空；不显示上一次查询结果 |
| 示例表执行低库存预警 | 返回洗衣液，库存8、预警值10 |
| 修改商品名称或价格 | 原编号和库存不变 |
| 排序显示 | 显示顺序改变，原表存储顺序不变 |
| 非法文件导入 | 报告失败，现有商品表不变 |
| 保存后重启并导入 | 商品字段、数量和统计结果保持一致 |
| 随机生成后再次生成 | 编号仍不重复，字段和容量合法 |
